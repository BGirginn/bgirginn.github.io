# MASTER WEBSITE SPECIFICATION

## bgirgin.dev

### Version 1.0

### Part 4 — Final Master Specification, Non-Negotiable Rules, Acceptance Criteria & Definition of Done

---

# 76. Final Product Definition

bgirgin.dev is a premium engineering brand website for Bora Girgin.

It is **not**:

```text
A generic portfolio
A blog
A dashboard
A startup landing page
A personal diary
A CV website
A cyberpunk showcase
```

It is:

```text
An engineering brand experience
A technical credibility platform
A premium presentation layer for embedded systems work
```

The website exists to communicate:

> Hardware, firmware and system-level engineering are designed together.

---

# 77. Primary Message

Every design decision must reinforce:

```text
Embedded Systems
PCB Design
Firmware Development
System Thinking
```

If an effect, animation, section, visual element or component does not support that message:

```text
Remove it.
```

---

# 78. The One Rule

The site has only one signature moment.

```text
PCB Layer Separation
+
Signal Flow
```

This is the identity of the website.

No other animation should compete with it.

---

# 79. Design Priorities

Priority order:

```text
1. Content
2. Clarity
3. Accessibility
4. Performance
5. Motion
6. Visual Effects
```

Never reverse this order.

---

# 80. Engineering Principles

The website itself should behave like a well-designed embedded product.

Meaning:

```text
Predictable
Reliable
Efficient
Purposeful
```

Not:

```text
Flashy
Noisy
Over-engineered
Unstable
```

---

# 81. Non-Negotiable Visual Rules

## Rule 1

No neon aesthetic.

Forbidden:

```text
RGB glow
Cyberpunk gradients
Gaming effects
Rainbow lighting
```

---

## Rule 2

No startup clichés.

Forbidden:

```text
Rocket icons
Growth charts
Disruptive messaging
AI hype language
```

---

## Rule 3

No luxury-watch overuse of gold.

Gold usage:

```text
Accent only
```

Maximum:

```text
2–3% visual presence
```

---

## Rule 4

Whitespace is mandatory.

Never compress content.

The website should feel:

```text
Expensive
Confident
Calm
```

---

## Rule 5

Typography is the primary visual tool.

Not effects.

Not gradients.

Not animations.

Typography.

---

# 82. Non-Negotiable Motion Rules

## Motion Language

Motion must feel:

```text
Mechanical
Precise
Controlled
Technical
```

Not:

```text
Playful
Bouncy
Cartoon-like
Energetic
```

---

## Continuous Motion Budget

Maximum:

```text
2 continuous animations
```

Allowed:

```text
PCB floating
Signal pulse
```

Nothing else.

---

## Signature Animation Budget

Maximum:

```text
1
```

Already assigned:

```text
PCB Layer Separation
```

No second signature sequence may be added.

---

## Reveal Budget

Maximum:

```text
3 major reveal sequences
```

Entire website.

---

Every section must answer a question.

---

Hero:

```text
Who is this?
```

---

Signature:

```text
Do they understand systems?
```

---

Work:

```text
What have they built?
```

---

Process:

```text
How do they think?
```

---

Capabilities:

```text
What tools and technologies do they use?
```

---

About:

```text
What kind of engineer are they?
```

---

Contact:

```text
How can I reach them?
```

---

If a section cannot answer its question:

```text
Rewrite it.
```

# 85. Copywriting Rules

Use:

```text
Short sentences
Technical language
Concrete statements
```

Avoid:

```text
Buzzwords
Marketing language
Motivational language
```

Forbidden words:

```text
Rockstar
Ninja
Guru
Disruptive
Revolutionary
Passionate
Visionary
```

---

# 86. Mobile Philosophy

Mobile is not a reduced desktop.

Mobile is its own product.

---

Desktop goal:

```text
Immersion
```

---

Mobile goal:

```text
Speed
Clarity
Reliability
```

---

If a desktop effect harms mobile usability:

```text
Remove it on mobile.
```

---

# 87. Performance Philosophy

Performance is a feature.

Every animation must justify its existence.

---

If an effect causes:

```text
Lower FPS
Longer loading
Poor Lighthouse score
```

The effect loses.

---

Performance always wins.

---

Accessibility is not optional.

Minimum standard:

```text
WCAG AA
```

---

Required:

```text
Keyboard navigation
Reduced motion
Semantic HTML
Visible focus states
Contrast compliance
```

---

# 92. Acceptance Criteria

The project is accepted only if all of the following are true.

---

## Brand

A first-time visitor understands:

```text
Who Bora Girgin is
What he does
Why he is qualified
```

within:

```text
10 seconds
```

---

## Visual

The website feels:

```text
Premium
Technical
Reliable
```

without feeling:

```text
Corporate boring
Startup generic
Cyberpunk flashy
```

---

## Motion

Signature scene works.

Layer separation works.

Signal flow works.

Nothing competes with them.

---

## Mobile

Mobile experience is smooth.

No broken layouts.

No unusable 3D.

No lag.

---

## Performance

Must achieve:

```text
LCP < 2.5s
CLS < 0.05
INP < 200ms
```

---

## Accessibility

```text
Pass
```

```text
Pass
```

```text
Pass
```

---

## Forms

```text
Validation works
Rate limiting works
Email delivery works
```

---

## SEO

Open Graph preview works.

Metadata works.

Structured data works.
